# Android Release (Google Play)

How the Tour-op Android app is configured, how to run it, and the steps to publish it on Google Play.

App ID: `com.tourop.app`. All native settings live in `mobile/app.json` and `mobile/eas.json`. The `mobile/android/` folder is generated by `npx expo prebuild` and is not committed, so never edit it by hand.

---

## 1. What is configured

| Area | Setting | Where |
|---|---|---|
| Server | Builds call `https://api.tour-op.com` (`EXPO_PUBLIC_API_URL`) | `eas.json` → every build profile |
| Notifications permission | `POST_NOTIFICATIONS` declared. The app creates the `default` channel and then shows Android's *Allow notifications?* prompt right after sign-in | `app.json` → `android.permissions`, `src/lib/push.ts` |
| Notification look | Small icon `assets/notification-icon.png` (white pin), teal accent `#0F766E` | `app.json` → `expo-notifications` plugin |
| Logo | Same mark as the website (`frontend/public/favicon.svg`: white pin on teal). Launcher icon, adaptive icon layers, splash screen, the in-app header (`src/components/Logo.tsx`) and `assets/store/play-icon-512.png` for the Play listing | `assets/`, `app.json` → `expo-splash-screen` plugin |
| Light / dark | Follows the phone's setting (`userInterfaceStyle: automatic`), or the System / Light / Dark choice on the Profile screen (`src/lib/theme.ts`, saved in SecureStore). Light uses a white background. Both palettes are in `src/components/ui.tsx` (`colors`). Read colours at render time and use `Text` from `ui.tsx`, not from `react-native`, so text gets the theme colour | `app.json`, `src/components/ui.tsx`, `src/app/_layout.tsx` |
| Google button | Google's multi-colour "G" (`assets/google-g.png`), as Google's branding rules require | `src/components/GoogleButton.tsx` |
| Removed permissions | Camera, microphone, overlay and old storage permissions are blocked. The app only picks existing photos (Android's photo picker needs no permission) | `app.json` → `android.blockedPermissions` |
| Versions | `version` 1.0.0 is shown to users. EAS keeps the `versionCode` and raises it on every production build | `app.json`, `eas.json` (`appVersionSource: remote`, `autoIncrement`) |
| Build types | `development` (dev client), `preview` (installable APK for testers), `production` (AAB for Play) | `eas.json` |
| Submit | Uploads to the **internal testing** track as a draft | `eas.json` → `submit.production` |

The itinerary screen in the app suggests recommended places too (see SeedingAndSafetyTesting §1.3).

## 2. Run it locally on the emulator

```powershell
cd D:\tour-ops\mobile
$env:JAVA_HOME = "$env:LOCALAPPDATA\Android\jdk"
$env:EXPO_PUBLIC_API_URL = "https://api.tour-op.com"   # or leave unset to use your local backend
npx expo run:android
```

This starts the `TourOps_Pixel` emulator if it isn't running, builds a debug app, installs it and starts Metro.

## 3. One-time setup (needs your accounts)

1. ✅ **Expo:** project `@nguyenquyhai2002/tour-op` is linked (`extra.eas.projectId` in `app.json`). The Android upload keystore was generated and is stored by EAS.
2. ✅ **Firebase app:** project `tour-op`, Android app `com.tourop.app`. `mobile/google-services.json` is git-ignored. Cloud builds get it from the EAS secret file variable `GOOGLE_SERVICES_JSON` (see `app.config.js`). To update it: `npx eas-cli@latest env:create --name GOOGLE_SERVICES_JSON --type file --value ./google-services.json --visibility secret --environment production --environment preview --environment development --force`.
3. ⬜ **FCM V1 key (lets Expo send pushes through Firebase):**
   - In Firebase → Project settings → Service accounts, click *Generate new private key*.
   - Upload the JSON on expo.dev → tour-op → Credentials → Android → `com.tourop.app` → *FCM V1 service account key*. Don't put this key in the repo.
4. ✅ **Server:** `EXPO_PUSH_ENABLED=true` is set (2026-10-08) on the Railway **api** and **worker** services.
5. ⬜ **Google sign-in on Android:**
   - Copy the SHA-1 fingerprints: the upload key from expo.dev → Credentials → Android, and the *App signing key* from Play Console → Test and release → App integrity (after the first upload).
   - The SHA-1 values (public, safe to share):
     - Play app signing key (used by installs from Play): `01:34:7F:9E:E7:BA:A7:66:CB:51:8D:E0:12:0E:68:E6:1A:0E:B9:D5`
     - EAS upload key (used by APKs installed directly from EAS): `64:97:EB:EA:26:32:3D:30:71:8E:80:3D:B9:95:BA:70:CE:AD:6B:1F`
   - ✅ Done 2026-10-11: Android clients `tour-op-android-play` and `tour-op-android-eas` were created in the Google Cloud project `analytical-rig-469404-e3` ("My First Project"). The older client `tour-op-android` is for the old package `vn.tourops.app` and is not used.
   - ⬜ The OAuth consent screen is still in **Testing** with 0 test users, so Google sign-in only works for listed test users. To publish it: remove `http://tour-op.com` from the web client's JavaScript origins (Google allows only HTTPS for "In production"), complete the Branding page, then click *Publish app* on the Audience page.
   - In Google Cloud Console (the project that owns the web client ID), create an **Android** OAuth client for `com.tourop.app` with each SHA-1. The app keeps using the web client ID (set in `eas.json`), so no code change is needed.
6. ⬜ **Play Console:**
   - Create the app *Tour-op*.
   - For `eas submit`, create a Google Cloud service account with access to the app (Play Console → Users and permissions), and download its JSON key as `mobile/google-play-service-account.json` (git-ignored).

Public build settings (API URL, Google web client ID) live in `eas.json` → `env`, because `mobile/.env` is not uploaded to EAS.

## 4. Build and publish

```powershell
cd D:\tour-ops\mobile
npx eas-cli@latest build --platform android --profile preview      # APK to try on a real phone
npx eas-cli@latest build --platform android --profile production   # AAB for Play
npx eas-cli@latest submit --platform android --profile production  # upload to internal testing
```

The very first upload must be done by hand in Play Console (Internal testing → Create release → upload the `.aab`). After that, `eas submit` works.

## 5. Play Console listing checklist

- [ ] **Privacy policy URL:** `https://tour-op.com/privacy` (English and Vietnamese, follows the site language). It is a draft: have it reviewed, ideally by a lawyer, before the production release.
- [ ] **Account deletion:** in the app (Profile → Delete account) and on the web (Account → Delete account). The URL for Play's *Data deletion* question is `https://tour-op.com/delete-account`. Deleting anonymises the account: personal data and photos are erased at once, while bookings, messages, reviews and reports stay as "Deleted user". Open bookings must be finished or cancelled first.
- [ ] **Contact mailbox:** the privacy and deletion pages tell people to email `support@tour-op.com`. Make sure that address receives mail (it is set in `frontend/src/pages/PrivacyPage.tsx`).
- [ ] Data safety form: the app collects name, email, phone, photos, messages and approximate location (city), all sent over HTTPS, and nothing is sold or shared for ads.
- [ ] Content rating questionnaire, target audience 18+ (sign-up rejects under-age users), and Ads: *No ads*.
- [ ] Store listing: short and full description in English and Vietnamese, the 512×512 icon (`mobile/assets/store/play-icon-512.png`), a 1024×500 feature graphic and at least 2 phone screenshots.
- [ ] A test account for Google's reviewers (email and password) under App content → App access, because most screens need sign-in.
- [ ] New personal developer accounts must run a closed test with at least 12 testers for 14 days before production access.
